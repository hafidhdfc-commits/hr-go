# RCA — build_image failure (run 62d7b31a-214f-4ec1-8fe7-7a8ae8061e25)

Deployment: `hr-go-local` (35187959-96c1-41af-a5b6-a9e50eccf2e1)
Template assigned: `fastapi_react_mongo_shadcn_base_image` (FARM family)
Frontend type: cloudflare · Architecture: arm64 · Tier: tier_0
Failed step: **build_image** (frontend-build stage, `yarn install`)

## Symptom (what the pipeline reported)
`yarn install` in the frontend-build stage failed all 3 retries with:
```
error @react-native/dev-middleware@0.86.3: The engine "node" is incompatible with this module.
Expected version "^20.19.4 || ^22.13.0 || ^24.3.0 || >= 25.0.0". Got "20.19.2"
error Found incompatible module.
```
yarn-classic hard-errors on an `engines.node` mismatch, so the install aborts.

## Root cause — template/architecture mismatch (NOT a one-line engine fix)
The app is an **Expo / React Native** project, but it was assigned the **FARM (React web)** deployment template. Evidence (read from the pulled source in a sandbox):

- `frontend/package.json`: `"main": "expo-router/entry"`, direct deps `expo@57.0.25`, `react-native@0.86.3`, `expo-router@57.0.23`, etc. Scripts are `start`/`android`/`ios`/`web` (`expo start ...`) and `lint` — **there is no `build` script**.
- `frontend/app.json`: full `expo` config; `web.bundler: "metro"`, `web.output: "single"` (so the app IS web-exportable — via `expo export --platform web`, which emits `dist/`).
- `@react-native/dev-middleware@0.86.3` is a transitive dep of `react-native@0.86.3` (in `yarn.lock`), and it is what declares `engines.node >= 20.19.4`.

The FARM `Dockerfile.cloudbuild` frontend-build stage runs:
```
retry_with_backoff yarn install --prefer-offline --check-files --network-timeout 100000 && yarn build
```
and then copies CRA `build/` or Vite `dist/` to the image. Two things are wrong for an Expo app:
1. The FARM frontend base image (platform-injected `FRONTEND_IMAGE`) ships **node 20.19.2**, below the `>=20.19.4` that Expo/RN 0.86 requires → the observed install failure.
2. Even if install passed, **`yarn build` does not exist** in this package.json. The correct Expo web build is `expo export --platform web` (produces `dist/`), which the FARM Dockerfile never invokes.

So the node-engine error is only the first failure; the deployment is structurally built with the wrong template.

## Verification performed
- Spawned an eph sandbox on this run's source. The sandbox node is `v20.20.2` (satisfies the engine), confirming the engine error is purely the build image's node version, not a source bug.
- Read `frontend/package.json`, `frontend/app.json`, `frontend/metro.config.js`, `frontend/yarn.lock`, and the FARM `Dockerfile.cloudbuild` / `build-frontend-artifacts.sh` directly.
- `get_deployment_manifest` for `Dockerfile.cloudbuild` and `build-frontend-artifacts.sh` → no GCS overrides exist; the build uses the stock FARM platform templates.
- NOT verified: a full `yarn install`/`expo export` run (would need network + time; not required — the missing `build` script and template mismatch are conclusive from source).

## Why I did not fix it with a manifest edit
Making the FARM Dockerfile build an Expo app would require fabricating an Expo static-export + R2 pipeline (swap `yarn build` → `expo export --platform web`, map output `dist/`, and `--ignore-engines`/node bump for the platform-injected base image). The authoring skill explicitly cautions against fabricating a manifest set with no authoritative reference, and this is unsafe within the 2-edit budget. The correct structural fix is to deploy with the **Expo template family**, which cannot be selected via manifest tools.

## Recommended fix
- **Platform (primary):** Re-deploy this job using the **Expo template** family (the one whose build runs `expo export --platform web` and ships a node runtime ≥20.19.4), instead of `fastapi_react_mongo_shadcn_base_image` (FARM). The frontend is already web-capable (`app.json` → `web.output: "single"`), so no source change is required for the web export to run under the correct template.
- If a native/web decision is needed, confirm intent (this is a mobile-first Expo project configured for web single-page export) before re-deploying.
