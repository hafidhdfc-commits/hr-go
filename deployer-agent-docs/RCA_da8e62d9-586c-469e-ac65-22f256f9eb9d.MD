# RCA — Deployment build_image failure (hr-go-local)

## Summary
The build fails at `build_image` (frontend-build stage). There are **two distinct problems**; the first was fixed via a manifest edit, the second is a **template / app-type mismatch** that needs E1 to act. The app did NOT go live.

## Deployment facts
- Deployment: `hr-go-local` (id 35187959-96c1-41af-a5b6-a9e50eccf2e1)
- Template in use: `fastapi_react_mongo_shadcn_base_image` (FARM / web-React, cloudflare frontend)
- Failing step: `build_image`
- Runs: f651afdc… and 62d7b31a… (engine error), da8e62d9… (post-fix, "build not found")

## Problem 1 — yarn engine check failed (FIXED by manifest edit)
Original build error:
```
error @react-native/dev-middleware@0.86.3: The engine "node" is incompatible with this module.
Expected version "^20.19.4 || ^22.13.0 || ^24.3.0 || >= 25.0.0". Got "20.19.2"
error Found incompatible module.
```
The prod build image ships node **20.19.2**; a react-native transitive dep requires ≥20.19.4.
Fix applied: added `--ignore-engines` to `yarn install` in `Dockerfile.cloudbuild` (frontend-build stage), `build-frontend-artifacts.sh`, and `Dockerfile`. This resolved the engine failure — install now completes.

## Problem 2 — wrong template for an Expo app (NEEDS E1 / UNRESOLVED)
After install succeeded, the build failed on the next command:
```
error Command "build" not found.
```
Root cause: the frontend is an **Expo / React Native** project, not a web-React (CRA/Vite) app.

Evidence from source (`/app/scratch/frontend`):
- `package.json`: `"main": "expo-router/entry"`, deps include `expo@57.0.25`, `expo-router`, `react-native@0.86.3`, `react-native-web`. **Scripts are `start/android/ios/web/lint` — there is NO `build` script.**
- `app.json`: `"web": { "bundler": "metro", "output": "single" }` — an Expo managed web app.

The FARM/shadcn template's frontend build runs `yarn install && yarn build` and expects a `build/` (CRA) or `dist/` (Vite) output served by nginx. An Expo project does not define `yarn build`; its web build is produced by `expo export` (metro), which Expo writes to `dist/`. So `yarn build` errors with "Command build not found".

This is a **template selection mismatch**: an Expo app was committed to a deployment configured with the web-React template. Patching the FARM manifest to emulate an Expo web export (`npx expo export --platform web`) was deliberately NOT attempted — it is speculative across both build and serve (expo-router SPA routing, metro web output, EXPO_PUBLIC_/react-native-dotenv env model vs the template's REACT_APP_BACKEND_URL sed-rewrite, and the prod node 20.19.2 being below what expo 57 / RN 0.86 expect). The platform has a dedicated Expo/EAS template family for exactly this.

## Recommended fix (E1 / main agent)
Deploy this app with the correct **Expo (expo/eas) template** instead of `fastapi_react_mongo_shadcn_base_image`, OR, if the intent is a web React app under the FARM template, the frontend must be a web-React project (CRA/Vite with a real `yarn build` producing `build/`/`dist/`) rather than an Expo/React-Native project.

The `--ignore-engines` manifest fix for Problem 1 is already staged in GCS and is still valid/needed for any react-native-based build; it can be kept.
